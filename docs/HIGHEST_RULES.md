# 《九州武侠》最高规则

本文件优先级高于普通阶段计划与临时实现方案。后续设计、数据和代码与本文件冲突时，以本文件为准。

1. **零内购**：禁止充值、VIP、抽卡、付费战力与商城绝学。
2. **活江湖**：玩家不行动时，NPC、势力、战争和事件仍继续运行；原著剧情可被改变。
3. **跨作品战力不平权**：只按实际表现、明确设定与可靠战绩定标，不因人物名气或作品地位强行抬战力。
4. **《风云》只采用第一部、第二部**：不继续向第三部扩张力量体系。
5. **战斗必须动态可视**：正式战斗不得退化为纯文字互扣血。
6. **稳定 ID + 可迁移存档**：国家、地点、NPC、势力、武学、物品、事件全部使用稳定 ID；存档从第一版开始保留 schema 与迁移入口。
7. **持续拆分是永久最高规则**：当前 `core/player/world/npc/faction/martial/combat/combat-render/event/item/save/data/ui` 只是第一层结构，不是最终结构。以后任何文件、目录或模块只要职责变多、体积增长、耦合升高或维护困难，就继续向下拆；可以不断新增子目录、新模块和数据包。宁可文件多，也不允许重新形成几十万字节的巨型核心文件。`src/` 单个业务文件超过 48 KiB 必须拆分，测试会直接阻止通过。

## 架构判断原则

是否需要继续拆，不看“现在已经有多少目录”，只看：

- 一个文件是否承担多个独立职责；
- 多个作品/国家的数据是否正在混入同一文件；
- 修改一个系统是否容易误伤无关系统；
- 是否难以单独测试；
- 是否已经接近或超过源码体积硬限制。

满足任意一项时，优先拆分，而不是继续往原文件追加。
