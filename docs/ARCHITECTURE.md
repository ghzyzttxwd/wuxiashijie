# 九州武侠工程架构

从第一天禁止巨型单文件。逻辑、数据、表现、存档分离。

- `src/core/`：游戏循环、时钟、随机数、全局状态
- `src/player/`：玩家角色、属性、出身、外挂、成长
- `src/world/`：国家、地区、地点、世界时间与旅行
- `src/npc/`：NPC实体、AI、日程、关系
- `src/faction/`：门派、朝廷组织、外交和势力状态
- `src/martial/`：武学、学习、熟练、内功、招式
- `src/combat/`：战斗规则、时间轴、伤害、战斗AI
- `src/combat-render/`：Canvas渲染、动画、粒子、镜头、技能特效
- `src/event/`：动态事件、剧情链、传闻
- `src/item/`：物品、装备、秘籍
- `src/save/`：多档位、schema、迁移
- `src/data/`：纯数据，按类别、国家、作品、体系继续拆分
- `src/ui/`：页面和面板，只负责交互显示

## 永久拆分规则

上述目录只是第一层拓扑，不是固定上限。以后任何模块只要职责增多、耦合上升、数据量增长或难以单独测试，就继续拆出子模块、子目录和数据包。后续新增 `simulation/`、`relationship/`、`rumor/`、`travel/`、`ai/` 等目录都属于正常演进，不得因为已有目录结构而把新职责硬塞进旧文件。

硬规则：

1. 单个业务文件不得无限膨胀；`src/` 下单文件超过 48 KiB 必须拆分，自动测试负责拦截。
2. 数据优先拆到 `src/data/*`，并继续按国家、作品、体系细分。
3. 核心系统只通过稳定 ID 引用声明式数据，不使用中文显示名作为主键。
4. 战斗规则与 Canvas 表现层隔离；NPC 规则与 NPC 数据隔离；存档迁移与业务逻辑隔离。
5. 需要时可以无限继续拆分；“宁可文件多，不要巨型核心文件”属于项目最高规则。
