# 数据层规则

`src/data/` 只保存声明式数据，不保存游戏流程逻辑。

## 当前分类
- `attributes.js`：七项基础属性定义
- `origins.js`：V0.1 出身数据；数量继续增长时按阶层/国家继续拆
- `talents.js`：唯一外挂数据；数量继续增长时继续拆
- `countries/`：国家/政权
- `locations/`：地区/地点/场景
- `npcs/`：NPC，按国家与作品拆
- `factions/`：门派、帮会、朝廷机构
- `martial/`：武学，按作品/体系拆
- `items/`：装备、秘籍、药品等
- `assets/`：出身资产、身份资源、组织入口等
- `events/`：事件定义
- `power/`：跨作品战力锚点与人物阶段版本

## 硬规则
1. 使用稳定 ID 互相引用，不通过中文名称做主键。
2. 数据文件必须按领域、国家、作品和体系继续细分。
3. **目录本身也可以继续拆。** 当前分类不是终局；只要单目录内容过多或职责开始混杂，就新增下一层目录。
4. 单文件明显膨胀时必须拆分；`src/` 下超过 48 KiB 的业务文件由自动测试直接判失败。
5. 逻辑代码不得复制进数据文件；Canvas 表现不得写进战斗规则文件。
6. 出身的银两、物品、初始武学、身份资产必须结构化保存并通过稳定 ID 引用，禁止把“银两×800”“高级护卫”这种显示文字直接当存档数据。
